# Claude Code 燃費最適化ノウハウ

職場で Claude Code を長時間・高効率に使うための運用ルール。

対象作業は主に以下。

- C言語の現状動作調査
- 設計書・計画書の作成
- 実装
- パステスト / ビルド / テスト

---

## 0. 基本思想

> **キャッシュを守る ＞ 読ませない ＞ 喋らせない ＞ 定型作業は機械にやらせる**

Claude Code の利用枠を節約するうえで、最優先はプロンプトキャッシュを維持すること。

出力を数百〜数千 token 減らすことも重要だが、巨大なコンテキストをキャッシュミスして再処理する方が影響が大きい。

合言葉:

> **キャッシュを切らすな。親を着替えさせるな。違う仕事は子にやらせろ。**

---

## 2. キャッシュ最優先ルール

### 2.1 朝イチ

会社環境では `/usage` で Prompt Cache TTL = **1時間** を確認済み。

前日から長いセッションを引き継ぐ場合、朝イチはキャッシュが失効している前提で考える。

その状態で巨大な前日コンテキストをそのまま再構築するより、

1. 朝イチで compact
2. 小さくなったコンテキストから開始
3. 以後はキャッシュを維持

を基本運用とする。

ただし、前日のセッション自体が短い場合は無理に compact しない。

### 2.2 日中

- できるだけ同じ親セッションを継続する
- キャッシュが生きている間は不要な compact をしない
- 長時間離席などで TTL 超過が見えた場合だけ維持策を考える
- コンテキスト上限や品質低下が見えた場合は途中 compact を許可する

### 2.3 TTL維持用の最小投稿

必要な場合のみ、最小の keep-alive 投稿を使う。

CLAUDE.md に次のようなルールを置く案:

```text
"." だけ送られた場合は "OK" のみ返す。
説明、ツール利用、追加提案は禁止。
```

運用例:

```text
.
```

応答:

```text
OK
```

目的は会話することではなく、キャッシュ TTL の更新。

## 3. Model / Effort を親で変えない

同じ親セッションで Model または Effort を変更すると、キャッシュ効率を悪化させる可能性がある。

したがって親セッションは原則固定する。

### 親セッション

役割:

- 全体コンテキスト保持
- 設計判断
- 方針決定
- 作業分解
- サブエージェントへの指示
- 結果統合
- 次アクション判断

### 別モデル / 別Effortを使いたい場合

**親自身を変更しない。**

限定作業として subagent に渡す。

例:

- 実装だけ別モデル
- 独立レビューだけ高Effort
- 大量調査だけ軽量モデル
- ログ解析だけ専用subagent

イメージ:

```text
親 Claude
  |
  +-- 調査 subagent
  +-- 実装 subagent
  +-- レビュー subagent
  +-- ログ解析 subagent
```

親は「司令塔」、子は「作業員」。

## 4. Outputを減らす

### 4.1 Concise を基本にする

Claude Code の出力を簡潔にする。

狙い:

- 作業開始宣言を減らす
- ツール利用前後の実況を減らす
- 長い最終まとめを減らす

### 4.2 実況禁止

不要な例:

```text
まず foo.c を確認します。
次に bar.h を読みます。
この関数を変更します。
変更できました。
次にテストします。
```

理想:

```text
[Claudeが裏で Read / Edit / Test]

実装完了。3ファイル変更。テストPASS。
```

### 4.3 再掲禁止

以下はチャットへ再掲しない。

- ファイルに書いたコード全文
- diff全文
- 設計書に書いた内容の再説明
- テスト成功ログ
- 既に成果物へ書いた長文

成果物へ直接書き、最終回答だけ短くする。

例:

```text
design.md 更新済み。
主変更: 3点。
```

### 4.4 PASSは短く、FAILだけ詳しく

テスト成功:

```text
PASS
```

または:

```text
実装完了。全テストPASS。
```

失敗時のみ:

- 失敗テスト名
- file:line
- 要点
- 次の対応

を返す。

## 5. C言語の現状調査を軽くする

現状調査では、親Claudeに大量のファイルを読ませない。

### 悪い流れ

```text
grep
↓
候補50ファイル
↓
20ファイルRead
↓
親Context肥大
```

### 良い流れ

```text
対象関数
↓
LSP / 定義へ移動
↓
参照元
↓
必要な関数だけ読む
↓
結論だけ親へ戻す
```

### 調査subagent案

専用 `c-researcher` を作る。

ルール例:

```text
目的:
Cコードの現状動作調査のみ行う。

制約:
- ファイル変更禁止
- Read / Grep / Glob / LSP 中心
- 必要以上にファイルを読まない
- コード全文を親へ返さない

親への返却:
- 最大5項目
- file:line
- 現状動作
- 根拠
- 不明点
のみ。
```

大量の調査過程は子のContext内で捨て、親には結果だけ残す。

---

## 6. 設計書・計画書

Claudeに「説明」と「成果物」の二重出力をさせない。

### 悪い例

```text
Claudeがチャットで設計を長文説明
↓
同じ内容を design.md に書く
```

### 良い例

```text
design.md を直接更新
↓
チャット:
「design.md 更新済み。主要変更3点。」
```

定型章立てや固定フォーマットは、できれば以下へ逃がす。

- Template
- VS Code snippet
- Script

Claudeには判断が必要な箇所だけ書かせる。

---

## 7. 実装

実装時は「黙ってEdit」が基本。

Claudeの仕事:

1. 必要箇所だけ読む
2. Edit
3. formatter
4. build
5. test
6. 結果だけ返す

途中説明は原則不要。

### CLAUDE.md候補

```text
- 作業中の実況をしない。
- ツール利用前後の説明をしない。
- ファイルへ書いたコードをチャットへ再掲しない。
- diffをチャットへ再掲しない。
- 成功時の最終報告は最大3行。
- テスト成功時は簡潔にPASSのみ報告する。
- 失敗時のみ原因、場所、次対応を簡潔に報告する。
- 詳細説明はユーザーが要求した場合のみ行う。
```

---

## 8. テスト / ビルドログ

ここは機械化効果が大きい。

生ログをそのままClaudeへ渡さない。

### 理想構成

```text
Claude Edit
   ↓
Hook / Script
   ↓
format
   ↓
build
   ↓
test
   ↓
raw log はファイル保存
   ↓
成功 → PASSだけ
失敗 → ERROR / FAIL周辺だけClaudeへ
```

### FAIL時に渡す情報

- テスト名
- file:line
- ERROR / FAIL 周辺
- expected / actual
- exit code

成功ログ1000行をClaudeに読ませる必要はない。

必要になったときだけClaudeが raw log を追加で読む。

## 9. Hookで逃がしたい処理

候補:

- clang-format
- build
- unit test
- static analysis
- テストログ圧縮
- ERROR / FAIL 抽出

判断不要の定型処理はClaudeにやらせず、Script / Hookへ寄せる。

## 10. CLAUDE.md に入れたい最重要ルール

```text
# Cache-first operation

最優先:
キャッシュを守る。
親セッションを着替えさせない。
違う仕事はサブエージェントへ渡す。

- 親セッションのModelを途中変更しない。
- 親セッションのEffortを途中変更しない。
- 別Model / Effortが必要な作業はsubagentへ委譲する。
- キャッシュ有効中は不要なcompactをしない。
- 長時間中断後、長大な履歴を再開するときはcompactを優先検討する。

# Output economy

- 作業中の実況をしない。
- ツール利用前後の説明をしない。
- ファイルへ書いたコードを再掲しない。
- diffを再掲しない。
- 成果物へ直接書く。
- 成功時は最大3行。
- PASS時は短く、FAIL時だけ詳細。
- 詳細説明は要求された場合のみ行う。
```

## 最終まとめ

Claude Codeの燃費改善は、細かいプロンプト短縮より順番が大事。

1. **キャッシュを守る**
2. **キャッシュを壊す操作を避ける**
3. **不要な情報を読ませない**
4. **不要な説明をさせない**
5. **定型処理をHook / Scriptへ逃がす**
6. **大量作業をsubagentへ隔離する**

> **Claudeに考えさせる。ただし、喋らせすぎない・読ませすぎない・着替えさせない。**
